# GeoSnap: next independent smartphone validation

No historical final/calibration population can be reused for a new independent claim. The 1,184 development queries have already been examined repeatedly; all v8 numbers from them are exploratory.

Freeze the selected research candidate before opening a new evaluation manifest: source revision, model and checkpoint hashes, gallery manifest/hash, preprocessing, inference sizes, candidate generation, ranker parameters, and confidence parameters (if any). Store the timestamped immutable candidate file outside production. Collect photographs only after this freeze.

Recruit new people and new capture sessions. Select Moscow routes and locations by a prespecified area/road-type grid, not by the current model's errors. Include both places with a nearby eligible gallery reference and places without one, then record that coverage stratum from the frozen gallery. Vary lighting, season and streetscape. Use independently captured smartphone photographs, with one designated primary single-image query per location; optional multiple views belong to a separate preregistered cohort. Keep the photographer/session together in any later resampling or fold design.

For every image, retain source JPEG/HEIC bytes, SHA-256, capture timestamp, photographer ID, session ID, device/camera metadata where available, and GPS ground truth with its acquisition method and estimated uncertainty. Avoid images with uncertain ground truth near the 25/50/100 m cutoffs. The location list and selection procedure should be committed before inference. Disallow query images, perceptual duplicates, or capture sequences found in the development set or gallery; investigate any collision before scoring. Do not use new query GPS in candidate generation, inference features, model fitting, or confidence fitting.

Run the frozen pipeline once on the sealed images, saving one prediction per query, top candidates/scores, runtime and inference artifact hashes. The evaluator at `ml/research/geographic_v8/independent_validation.py` validates the freeze, population identity, image hashes and one-prediction-per-query contract, then calculates RAW25/50/100/500/1km/5km, median, p90 and >500 m for the full denominator. Report covered/uncovered strata separately without removing either from the primary denominator. Use session/geographic clustered intervals. If multiple photos or confidence are evaluated, label them as separate frozen protocols. Do not turn this collection into another tuning set after looking at its outcomes.
