## One parallel reference-density correction (registered before results)

Repeated false matches in the bounded hard-negative inspection motivate one
new local-density correction. Code search found no prior CSLS/hubness/local
scaling trial. This does not subtract a uniform global mean or train a
projection: those negative families remain closed.

Choose4096 landmarks entirely from G2, one deterministic stable-ID frame per
normalized provider sequence, followed by a fixed hash order. For each reference
compute its mean cosine to its10 closest landmarks from other sequences.
Use exactly `cos(query,reference) - 0.5 * reference_density` for ranking,
all100k references and all1184 fixed dev queries, ordinary top1 coordinates.
One arm only: no coefficient, k, landmark-size or combination sweep.

The local-scaling motivation and two-sided formula come from
[Conneau et al., section2.3](https://arxiv.org/html/1710.04087v3#S2.SS3).
Our reference-only landmarks are an explicit population proxy: this is
CSLS-inspired, not a reproduction of the paper's cross-domain query-side
neighborhood estimation or its results. A query-constant term does not alter
ranking. No development query distribution, labels or coordinates are used to
fit the density; there is no cross-query dependence at inference.

Use cached8448-dimensional vectors, at most256 refs per block, one CPU thread,
nice10, ~138MB landmark matrix and one mapped descriptor shard. Cache the
landmarks and partial density once; predictions/results go to cpu_density/ and
publish only under controller.lock. The synthetic BLAS preflight is saved in
reference_density_cost_preflight.json; it suggests arithmetic is cheap but
excludes descriptor I/O, matrix packing and partition overhead, so it is not
a promised ETA. The real streaming pass reads~3.38GB, with no new image encoding.
Respect06:00 start cutoff; if negative, close immediately without tuning.
